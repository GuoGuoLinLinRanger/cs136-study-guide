CS 135 modelled Racket with substitution: a variable is a name for a value, and a function call is replaced by its body. CS 136 models C with two things instead: control flow (where the program location is) and memory (what every box holds). Almost every midterm question is one of two kinds:

The one picture to keep in your head A C program is in a state at every instant: the current program location plus the contents of memory (read-only data, global data, and one stack frame per active function call). Every statement either changes memory (assignment, scanf, mutation through a pointer), changes the location (if, loops, calls, return), or changes the outside world (printf). If you can say what each line does to that state, you can answer any trace question.

The design recipe template (memorize the shape)

Every "write a function" question is marked against this shape. Your quizzes lost marks on almost every line of it at least once, so it is worth more than any single topic.

#include "cs136.h"

// find_max_index(arr, len) returns the index of the first occurrence of the
//   largest element of arr                     <- names the function, says what it RETURNS
// requires: len > 0                             <- every precondition
//           arr is a valid array of len ints [not asserted]
// (effects: ... only if it prints, reads, or mutates something outside itself)
int find_max_index(const int arr[], int len) {  // every parameter has a TYPE; const for read-only
  assert(arr != NULL);                           // requirement asserts come FIRST, inside the function
  assert(len > 0);
  int max_index = 0;                             // every variable initialized
  for (int i = 1; i < len; ++i) {                // the loop variable is declared here
    if (arr[i] > arr[max_index]) {
      max_index = i;
    }
  }
  return max_index;                              // do not forget the return
}

int main(void) {
  int a[4] = {3, 7, 2, 7};                       // test data has a type and a size
  assert(find_max_index(a, 4) == 1);             // pass a, not &a; compare to an EXPECTED value
  int b[1] = {-5};
  assert(find_max_index(b, 1) == 0);
}
Watch out — the pattern behind your lost marks Across three quizzes the tracing and memory-diagram questions were perfect. The marks went on hand-written code that would not compile (a parameter with no type, a loop variable never declared, a missing return, variables used in main that were never defined, &a passed for an array) and on recipe details (asserts in the wrong place, a vague purpose statement, a base case that misses n == 0). The Mistakes Log lists every one with the fix.

Exam-day protocol for every "write a function" question

  1. Read the spec twice. Underline the return type, each parameter's type, every requirement, and the examples. The examples become your asserts.
  2. Write the header first, with every type: return type, name, each parameter with its type, const on arrays and pointers you only read. Check the names you will use in the body match the parameter names.
  3. Write the documentation: purpose line that names the function and says what it returns, prints or reads; requires: lines; effects: line only if there is a side effect.
  4. Open the brace and assert the requirements (one assert per requirement, assert(p != NULL) for every pointer that must be valid).
  5. Write the body. Initialize every variable. Declare the loop variable inside the for. For recursion, decide the base case by testing the smallest inputs (0, 1, a single digit) by hand.
  6. Check every path: every path of a non-void function returns a value; every path through a loop body moves toward the exit (no continue before the update).
  7. Write main: define the test data with a type and a size, define any output variables before the call, call the function, and assert each result against the expected value from the examples.
  8. Proofread for the classics: = vs ==, < vs <=, & on an array, a missing semicolon after a struct definition, void for no parameters, a successful main returns 0.

1.1 Expressions, operators and integer arithmetic

Definition — the C we use
  • CS 136 uses the C99 standard (1999). C11, C18 and C23 exist; nothing from them is needed.
  • A comment is either // to the end of the line or /* anything, even over several lines */.
  • Expressions use infix notation, 3 + 4 * 2, with normal arithmetic precedence. Racket used prefix, (+ 3 (* 4 2)). Use parentheses whenever the order is not obvious.
  • C has over 40 operators. There is no exponent operator: 2 ^ 3 is bitwise exclusive-or and evaluates to 1, not 8.
Watch out — comments do not nest /* this /* inner */ is an error */ ends at the first */, so the compiler then sees is an error */ as code and refuses to build. To comment out a block that already contains a block comment, use // on each line.

1.2 Identifiers and functions

Definition — identifiers An identifier (name of a function, variable or structure) must start with a letter and may contain only letters, digits and underscores. In CS 136 compound names use underscore_style: hst_rate, trace_int, quick_sort. Leading underscores (_name) are legal C but avoided here because they can collide with reserved names and break Marmoset tests. camelCase is the Java style, not ours.
Anatomy of a function 
// my_add(a, b) returns the sum of a and b
int my_add(int a, int b) {
  return a + b;
}
  • int before the name is the return type; int a, int b are typed parameters separated by commas.
  • The braces { } form the function block; return is followed by an expression and a semicolon.
  • Calling it: my_add(2, 3). The values 2 and 3 are the arguments; they become a and b inside the function.
In C we sayIn Racket we said

the function returns a value: "if 7 is passed to sqr, it returns 49"the function produces a value
a function has a return type and parameter types written in the codea contract comment
Definition — static type system Every type must be known before the program runs, and the type of an identifier never changes. Consequences you will be asked about:
  • You must write the return type and every parameter type. If you omit the return type, C assumes int and warns: type specifier missing, defaults to 'int'. Omitting it is very bad style and loses marks.
  • It is impossible to violate a type contract at run time. my_add("hello", 3) does not produce a runtime error; the compiler refuses to produce an executable, so the program never runs. There is no C equivalent of integer? or string?.
  • "Type error" therefore always means compile-time error in this course.
Definition — void parameters and no nested functions A function with no parameters is written int my_num(void) and called as my_num() (nothing between the parentheses, never my_num(void)). Writing int my_num() is legal but means "an unknown number of parameters" in old C, so in CS 136 you must write void. Functions cannot be defined inside other functions: every function is at the top level of the file.
Definition — function documentation (the part markers read first) Every function except main gets a comment immediately above it:
  • a purpose that shows a call and says what the function returns (not how): // safe_mod(x, y) returns the remainder when x is divided by y
  • a requires line for every precondition, copied precisely from the specification: // requires: y != 0. If the spec says n >= 0, do not write n > 0.
  • an effects line only when the function has a side effect (Chapter 2). Tracing and asserts are not effects.
  • no contract types: they are already in the definition.
A purpose like // returns what is left after dividing lost a mark on Quiz 1 because it names neither the function nor the parameters. Pattern to copy: // name(p1, p2) returns ..., or for a printing function, // name(p1) prints ....
Definition — CS 136 style rules you are marked on
  • Opening brace { at the end of the line that starts the block; closing brace } on its own line, aligned with the line that opened it.
  • Indent each block 2 (recommended), 3 or 4 spaces, consistently.
  • A space after every comma and around arithmetic and comparison operators: my_add(a, b), x + 1, n < 10.
  • Long parameter lists, expressions or purposes continue on the next line, indented.
  • Every if, else and loop body is a { } block, even for one statement.

Understand it this way Racket is interpreted: DrRacket reads your file from the top and runs each line, so the entry point is the top of the file. C is compiled: the compiler translates every .c file into one executable first, and if it finds any error there is no executable at all. The entry point of a C program is a special function, main, not the top of the file. Code outside functions never "runs".
Definition — main
  • Every C program has exactly one main. Its return type is int and (for us) it takes no parameters: int main(void).
  • The returned value is the program's exit code to the operating system. 0 means success; EXIT_SUCCESS is a constant defined as 0. A non-zero value signals an error, and on assignments it makes Marmoset tests fail.
  • main is special: return 0; may be omitted and 0 is returned automatically. The notes omit it to save space; on exams it is optional.
  • main needs no purpose comment. The program is documented with a comment at the top of the file.
The smallest complete program 
// A program that prints a greeting
#include "cs136.h"

int main(void) {
  printf("Hello World!\n");
  return 0;
}
#include "cs136.h" copies the course header into the file before compiling; it pulls in stdio.h (for printf), assert.h, stdbool.h, limits.h and the tracing tools. In plain C you would write #include <stdio.h>. The \n ends the line; without it the next output continues on the same line.
Watch out — no top-level expressions In Racket you could type (+ 1 1) at the top of a file and see 2. In C, code only executes inside functions: a line such as 1 + 1; or printf("hi"); outside every function is a compile error. Only definitions, declarations, #include lines and comments live at the top level.
Definition — tracing tools (cs136.h) trace_int(expr) prints the text of the expression, =>, and its value, for example trace_int(10 / 3 + 10 % 3); prints 10 / 3 + 10 % 3 => 4. There are also trace_char and (later) trace_ptr. Tracing goes to the stderr stream, printf goes to stdout; only stdout is tested, so leave your tracing in. Tracing is for informal checking; real testing uses assert.
Definition — declaration vs definition, and why order matters The compiler reads a file top to bottom. An identifier must be declared above the point where it is used. If main calls my_add and my_add is only written below main, you get a compile error: implicit declaration of function 'my_add' is invalid.
  • A declaration only states the type of an identifier. For a function it is the header followed by a semicolon, also called a prototype: int my_add(int a, int b);
  • A definition creates the identifier (for a function, the header plus the block). Every definition is also a declaration.
  • An identifier may be declared many times but defined exactly once.
  • In a prototype the compiler ignores parameter names: int my_add(int, int); is equivalent, but keep meaningful names for the reader.
#include "cs136.h"

int my_add(int a, int b);        // declaration: my_add exists and has this type

int main(void) {
  assert(my_add(2, 3) == 5);     // legal: declared above
}

int my_add(int a, int b) {       // definition: creates the function
  return a + b;
}
The quiz blank "the prototype for max taking two ints and returning an int" is exactly int max(int a, int b); with the semicolon.

1.4 Booleans, assert and testing

Truth in C
  • Boolean expressions produce an int: 0 for false, 1 for true. true and false are defined as 1 and 0.
  • Operators that produce a Boolean (== != < <= > >= ! && ||) always give exactly 0 or 1.
  • Operators that consume a Boolean (&& || !, if, loops) treat every non-zero value as true; only 0 (and later NULL) is false.

Watch out — the four operator typos = instead of == (assignment, Chapter 2: the condition becomes the assigned value, so if (i = 13) is always true and silently changes i); & instead of &&; | instead of ||; and < where <= was meant (off by one). Defensive habit: write (13 == i), so a dropped = becomes a compile error instead of a bug.
Definition — bool bool is an integer type whose value is only 0 or 1. Use it as the return type of predicates such as bool is_even(int n), and return true/false or a comparison directly: return n % 2 == 0; already produces 0 or 1, so if (n % 2 == 0) { return true; } else { return false; } is longer for no gain.
Definition — assert, the two jobs assert(exp) does nothing when exp is non-zero and stops the program with a message when exp is 0. It has two separate uses, in two separate places:
  1. Asserting a requirement, inside the function, as its first statements. One assert per requirement so a failure names the broken condition: assert(n >= 0); assert(d <= 9); rather than one combined assert.
  2. Testing, in main, comparing a call with an expected value: assert(safe_mod(7, 3) == 1);. A bare safe_mod(7, 3); tests nothing.
When all asserts pass the console is empty. That silence is the passing test. Asserts and tracing are not side effects and are never documented under effects.
Worked example — Quiz 1 Q5, written the way the marker wanted 
// A program that tests safe_mod
#include "cs136.h"

// safe_mod(x, y) returns the remainder when x is divided by y
// requires: y != 0
int safe_mod(int x, int y) {
  assert(y != 0);
  return x % y;
}

int main(void) {
  assert(safe_mod(7, 3) == 1);
  assert(safe_mod(9, 3) == 0);
  assert(safe_mod(2, 5) == 2);
  assert(safe_mod(-7, 3) == -1);
}
The submitted version put assert(y != 0) inside main, where y does not exist, and then called safe_mod(x, y) on variables that were never defined; both lines would stop the file from compiling. Two marks gone on a five-mark question.
Watch out — the marker's checklist for "write a complete function"
  1. #include "cs136.h" at the top when a complete program is asked for.
  2. Purpose comment that names the function and its parameters and says what it returns or prints.
  3. requires: copied exactly from the spec; [not asserted] when it cannot be checked.
  4. Return type and the type of every parameter; parameter names used consistently in the body.
  5. Requirement asserts as the first statements of the function.
  6. Braces on every branch; a return on every path.
  7. int main(void) whose asserts compare calls against expected values, including the smallest legal input (0, 1, the boundary) and a typical one. Any variable used in main is defined there first.
Definition — infeasible requirements Some requirements cannot (or should not, for efficiency) be checked with an assert. Still document them, and say so: // requires: n is a prime number [not asserted]. Everything that can be asserted cheaply must be asserted.
Definition — how to debug (the course method)
  1. Write tests first; start simple, work up to corner cases; think like an adversary trying to break the function.
  2. Fix one bug at a time; find the simplest test that triggers it.
  3. Form hypotheses (off by one, wrong boundary, loop exit condition, = vs ==), pick the most likely, test it with trace_int or extra asserts, rule hypotheses out one by one and keep notes.
  4. Check the tests as carefully as the code; the hardest bugs are in the assertion, not the function.
  5. If the code is a tangle, simplify: small, well-named helper functions are easier to read, test and fix.

1.5 Control flow and recursion

Definition — the four kinds of control flow Compound statements (blocks), function calls, conditionals (if) and iteration (loops, Chapter 3). A block { } is a sequence of statements executed in order. return is a control-flow statement: it ends the function immediately, so nothing after it in that block runs. A function call jumps to the start of the called function; its return jumps back to the caller. 
int f(int n) {
  trace_int(n);
  return n * 2;
  trace_int(7);         // never executes: the return above already left f
}
Conditionals 
if (expression) {
  // runs when expression is non-zero
} else if (other_expression) {
  // runs when the first was 0 and this one is non-zero
} else {
  // runs otherwise
}
  • if affects only the next statement. To control several statements you need a block, and in CS 136 you use a block even for one statement.
  • If an if branch ends with return, the else is optional; both styles are fine.
  • if is a statement, not an expression: it has no value and cannot sit inside a + if .... Racket's cond did produce a value.
  • The ternary operator q ? a : b is an expression whose value is a when q is non-zero and b otherwise: (v >= 0) ? v : -v is abs(v). Allowed, sparingly.
  • switch (fall-through behaviour) and goto are not allowed in CS 136.
Watch out — the dangling else 
if (a > 0)
  if (b > 0)
    printf("both positive\n");
else                                  // belongs to the NEAREST if (b > 0)
  printf("a is not positive\n");      // actually runs when a > 0 and b <= 0
Indentation means nothing to the compiler. With a = 5, b = -1 this prints a is not positive; with a = -5, b = 5 it prints nothing at all, because the whole inner if/else is the single statement controlled by the outer if. Braces make the intent unambiguous: 
if (a > 0) {
  if (b > 0) {
    printf("both positive\n");
  }
} else {
  printf("a is not positive\n");
}
Definition — three shapes of recursion Recursion in C works exactly as in Racket; only the syntax changes. The base case is the true branch of an if, the recursive case comes after. 
// sum_to(n) returns 0 + 1 + ... + n
// requires: n >= 0
int sum_to(int n) {
  assert(n >= 0);
  if (n == 0) {
    return 0;
  }
  return n + sum_to(n - 1);          // simple recursion: "+ n" still to do after the call
}
// sum_to_acc(n, acc) returns acc + 0 + 1 + ... + n
// requires: n >= 0
int sum_to_acc(int n, int acc) {
  assert(n >= 0);
  if (n == 0) {
    return acc;
  }
  return sum_to_acc(n - 1, acc + n); // accumulative: nothing left to do after the call
}

// sum_to(n) returns 0 + 1 + ... + n
// requires: n >= 0
int sum_to(int n) {
  assert(n >= 0);
  return sum_to_acc(n, 0);           // the wrapper initializes the accumulator
}
// is_odd(n) returns true if n is odd
// requires: n >= 0
bool is_odd(int n);                  // forward declaration: is_even calls is_odd, defined below

// is_even(n) returns true if n is even
// requires: n >= 0
bool is_even(int n) {
  assert(n >= 0);
  if (n == 0) {
    return true;
  }
  return is_odd(n - 1);
}

bool is_odd(int n) {
  assert(n >= 0);
  if (n == 0) {
    return false;
  }
  return is_even(n - 1);             // mutual recursion
}
Simple recursion leaves work pending after each call, which costs memory (Chapter 3 explains the stack frames). Accumulative recursion carries the partial answer in a parameter. Mutual recursion compiles only because is_odd is declared above is_even; remove the forward declaration and you get the implicit-declaration compile error.
Worked example — filling a trace table (Quiz 1 Q4, 5/5) 
int rev_helper(int n, int acc) {
  if (0 == n) {
    return acc;
  }
  return rev_helper(n / 10, (acc * 10) + (n % 10));
}

int reverse(int n) {
  return rev_helper(n, 0);
}
Method: write one row per call, compute the next row's arguments from the current row using the recursive call's expressions, stop at the base case, and state the value that is returned all the way up. 
call                    n      acc
rev_helper(1234, 0)     1234   0
rev_helper(123, 4)      123    4        n / 10 = 123, acc * 10 + n % 10 = 0 + 4
rev_helper(12, 43)      12     43
rev_helper(1, 432)      1      432
rev_helper(0, 4321)     0      4321     base case: returns acc = 4321
Final return value: 4321
The value returned by reverse(1234) is the base case's acc; the other frames just pass it up unchanged because nothing is added after the call.
Watch out — base cases that lose the last digit (Quiz 1 Q7, 4/5) count_digit(n, d) must count how often digit d appears in n, with n >= 0. A base case of n == 0 returns 0 for count_digit(0, 0), but the number 0 does contain the digit 0 once. The fix is to stop at a single digit, which handles every one-digit number including 0: 
// count_digit(n, d) returns the number of times the digit d appears
//   in the base-10 representation of n
// requires: n >= 0
//           0 <= d <= 9
int count_digit(int n, int d) {
  assert(n >= 0);
  assert(d >= 0);
  assert(d <= 9);
  if (n < 10) {
    return n == d;                       // 1 if the single digit is d, else 0
  }
  if (n % 10 == d) {
    return 1 + count_digit(n / 10, d);
  }
  return count_digit(n / 10, d);
}
Rule of thumb for digit recursion: if a single-digit input is a legitimate value with an answer of its own, the base case is n < 10, not n == 0. Also check the smallest allowed input (n = 0) and a single-digit input against the spec before you write the recursive case, and copy the requirement exactly (n >= 0, not n > 0).
Design-recipe skeleton to reproduce on every code question 
// name(p1, p2) returns ...           (or: prints ..., reads ... and returns ...)

    return ...;
  }

}

★ Must remember — Chapter 1
  • / truncates toward zero; % takes the sign of the left operand; i == (i / j) * j + i % j. Same precedence goes left to right: 100 / 10 / 2 is 5.
  • No exponent operator (^ is xor). 017 is 15, 010 is 8, 0x10 is 16: never write a leading zero.
  • Identifiers start with a letter; underscore_style; every type written; void for no parameters; no nested functions; comments do not nest.
  • Terminology: call a function, pass arguments, it returns a value.
  • Static typing: a type error is a compile-time refusal, never a runtime error. Calling an undeclared function is also a compile error.
  • int main(void); exit code 0 = success (EXIT_SUCCESS); return 0; optional in main; no top-level expressions; document the program at the top of the file.
  • Declaration = type only (int max(int a, int b);), may repeat; definition = creates it, exactly once. Declare before use; mutual recursion needs a forward declaration.
  • Booleans are 0 and 1; any non-zero is true; && and || short-circuit left to right; ! binds tightest, then * / %, + -, comparisons, == !=, &&, ||.
  • assert: requirements inside the function (one per requirement); tests in main compared to expected values; [not asserted] for infeasible requirements; tracing goes to stderr and stays in.
  • Purpose comment names the function and says what it returns; requires: copied exactly from the spec.
  • Braces on every if/else; else binds to the nearest if; if has no value, ?: does; no switch, no goto.
  • Recursion: simple (work after the call), accumulative (helper with acc, wrapper passes the start value), mutual (forward declaration). Digit recursion usually needs the base case n < 10 so that 0 and single digits are handled.
  • Trace tables: one row per call, next arguments computed from the recursive call's expressions, final value is what the base case returns.

Definition — state and side effect State is the value of some data at a moment in time. A side effect is anything a function does that changes state somewhere other than its own return value. In CS 136 a function has a side effect when it does one of these four things:

Definition — the two output streams and the two Run buttons

  • trace_int and the other tracing tools write to stderr (standard error). It is never compared, so leave your tracing in. In Run Code the two streams appear mixed together on screen.

Definition — void function A function whose return type is void returns nothing; it exists for its side effect. It has no return expression: either reach the closing brace or write a bare return; to leave early. Purists call it a procedure.

Where does the 7 go? printf is not void: it returns the number of characters it printed, so printf("hello!\n") returns 7 (five letters, the !, and \n, which counts as one character). Nobody uses the 7, so where does it go? It is thrown away, because of what a statement is.
Definition — expression statement, and the three kinds of statement An expression statement is an expression followed by a semicolon. C evaluates the expression, then discards the value. Its only purpose is the side effect, which is why imperative programming is "programming by side effects". The edX compiler warns when an expression statement obviously has no effect, such as 8 + 1;, but not when it contains a function call (a side effect is assumed).

2.2 Variables, mutation and assignment

Definition — variable definition int m = 5; has, in order: the type, the identifier, and the initial value. Giving the initial value is initialization. C lets you write int m; with no initial value, but that is bad style in CS 136: always initialize. A variable holds a value at every moment; changing that value is mutation, and mutation is a side effect because the state of the variable changes.
Assignment variable = expression;
  1. Evaluate the right-hand side (RHS) to a value of the variable's type.
  2. Store that value in the variable named on the left-hand side (LHS). The LHS must be a variable (for now).
  3. The assignment expression itself also produces the stored value, which is why x = y = 0; is legal. It is bad style: write two statements.
Assignment is not symmetric: x = y; copies y into x, y = x; copies x into y. Some languages write x := y or x <- y to make the direction obvious. Rule of style: one side effect per expression statement.
int main(void) {
  int m = 5;        // definition + initialization
  trace_int(m);     // m => 5
  m = m + 1;        // assignment: evaluate m + 1 (6), store it in m
  trace_int(m);     // m => 6
  m = -1;
  trace_int(m);     // m => -1
}
Watch out — the single most common C bug 
int i = 5;
if (i = 13) {            // BUG: assigns 13 to i; the expression's value is 13, which is "true"
  printf("disaster!\n");
}
trace_int(i);            // i => 13
= assigns and produces the assigned value; == compares. if (i = 13) always runs the block (13 is non-zero) and silently destroys i; if (i = 0) never runs it. Defensive habit: put the constant first, if (13 == i). Then the typo if (13 = i) is a compile error instead of a bug.
Definition — initialization is not assignment 
int n = 7;        // initialization: part of the definition; this = is NOT the assignment operator
n = 8;            // assignment: an expression statement that mutates n
int a = 0, b = 0; // legal but bad style: one variable per definition
int c, d = 0;     // legal, bad style, and c is UNINITIALIZED (the = 0 belongs to d only)
The distinction barely matters now; it matters later for arrays and structures, and enormously in C++. Rules for this course: initialize every variable, one variable per definition, define a variable as close to its first use as possible.

Definition — constants, global and local variables, arguments and parameters
  • const int tax_rate = 13; defines a constant: an immutable variable. tax_rate = 15; is a compile error. Use const whenever a value never changes: it communicates intent, prevents accidental mutation and can speed up the code. (In CS 136 the word "variable" covers both; say "mutable variable" vs "constant" when the difference matters.)
  • A global variable is defined outside every function (at the top level). A local variable is defined inside a function (inside a block).
  • A value passed to a function is an argument; the name in the function header that receives it is a parameter. Parameters behave like local variables.
  • Rule: global constants are great style and encouraged. Global mutable variables are banned on assignments unless a question explicitly allows them (Assignment Rule 12.1). Static local variables (locals that keep their value between calls) are banned outright.

2.3 Scope, shadowing and purity

Definition — scope The scope of an identifier is the region of code where it is visible (accessible). A global variable is in scope from its definition to the end of the file, so code above the definition cannot use it. A local variable has block scope: from its definition to the closing brace of the block it was defined in. Functions have scope too: a function is usable only below its declaration, which is why mutual recursion needs a forward declaration (Chapter 1). C99 lets you define a local anywhere in a block; define it in the narrowest scope that works, as close to its first use as possible.
Worked example — shadowing (the three g's) 
#include "cs136.h"

int g = 1;                // global g

int main(void) {
  trace_int(g);           // g => 1  (only the global g is in scope here)
  int g = 2;              // a NEW local g that shadows the global (poor style)
  trace_int(g);           // g => 2
  {
    int g = 3;            // a third g, visible only inside these braces
    trace_int(g);         // g => 3
  }
  trace_int(g);           // g => 2  (the block's g is gone; main's g is back)
}
Shadowing is legal and terrible style. On an exam it is a trace question: at each line ask "which definition of this name is the innermost one still in scope?"
Definition — pure and impure functions A function is pure when (1) it has no side effects and (2) its return value depends only on its argument values. Impure functions are sometimes called procedures or routines.

2.4 Reading input with scanf

int retval = scanf("%d", &x);
  • "%d": read one decimal integer, skipping any leading whitespace (spaces and newlines).
  • &x: the address of x, so that scanf can store the value it read into x (Chapter 4 explains the mechanism). Forgetting the & is a classic crashing bug.
  • In CS 136, read one value per scanf call.

Worked example — reading one int, two equivalent styles 
#include "cs136.h"

int main(void) {

Worked example — reading everything, recursively 
// print_forward() reads ints from input until no more can be read and
//   prints each one on its own line, in the order read

    printf("%d\n", n);        // print, THEN read the rest

// print_reverse() reads ints from input until no more can be read and
//   prints them in reverse order, each on its own line

  }

// count_even_inputs() reads ints from input until no more can be read
//   and returns how many of them are even

  return count_even_inputs();

Definition — how scanf("%d") walks through the input
  • Whitespace between numbers is irrelevant: 1 2 3 on one line and 1, 2, 3 on three lines are indistinguishable to %d.
  • Invalid input is never skipped. For the input 4 23skidoo 57: the first call reads 4 and returns 1; the second reads 23 and returns 1 (it stops at the s); every further call returns 0 because skidoo is still sitting there. The 57 is never read.

2.5 I/O testing, harnesses and testing vocabulary

Definition — the two testing strategies
  • Return values: asserts in main, one per test case, each comparing a call to a known answer: assert(sqr(7) == 49);. A call on its own, sqr(7);, tests nothing.
  • Input and output: Run With Tests with pairs of files name.in (what stdin contains) and name.expect (exactly what stdout must contain, final newline included). Only stdout is compared; stderr (tracing) is ignored.
Definition — testing harness A testing harness is a program (usually main plus a helper) that reads argument values from input, calls the function under test, and prints the results. Then every test is just an .in/.expect pair, so tests can be added without touching code, even by non-programmers. It works for pure and impure functions. A fancier harness reads a symbol first to decide which function to test: lookup_symbol("SQR") gives the int code for a symbol name, read_symbol() reads the next word of input and returns its code, and you compare the two before reading the argument with scanf. A line of such a test file looks like SQR 7.
Watch out — whitespace in .expect files A missing final newline, a trailing space, or 4 9 16 on one line when the program prints three lines all fail the test. Print exactly one result per line with "%d\n" and make the expect file match character for character. If a test fails and the outputs look identical, the difference is whitespace.

2.6 How to write a testing harness, for any function

A harness question gives you a function (or asks you to write one first) and says: "write a program that reads ... from input and prints ... for each". The function changes from exam to exam; the harness is always the same five decisions. Make them in this order and the code writes itself.

The harness recipe
  1. Decide what one test case looks like in the input. One case per call of the function, its arguments in order, separated by whitespace: 7 for square(7), 3 4 for my_max(3, 4), 3 10 20 30 for an array (length first, then the elements), s 7 when a command letter chooses the function.
  2. Decide what one case prints. Exactly the result and a newline: printf("%d\n", f(x)). A bool prints as 1 or 0 with %d unless the question asks for words. A function that returns nothing but mutates through pointers or an array: print the mutated values after the call. A function that itself prints: just call it; print nothing else. Never print prompts, labels or the inputs back: they go to stdout and break the expect file.
  3. Define every variable the call needs before the loop, initialized: int a = 0; int b = 0; Output variables for pointer parameters: int q = 0; int r = 0; Arrays: a fixed buffer with a literal size, int a[100]; plus int n = 0;.
  4. Read one whole case per iteration, and stop when any read fails. One %d per value, each checked: while (scanf("%d", &a) == 1 && scanf("%d", &b) == 1). For a character use " %c" with the leading space; for a word "%80s" into char w[81]. An array is read with an inner loop after its length.
  5. Call the function and print. Then document: purpose "name() reads ... from input and prints ... for each", effects: reads input, produces output, return type void (or make main the harness), no requires: line unless the input format imposes one (then assert it). Finally write the .in/.expect pair by hand from the question's examples plus edge cases.

Watch out — the ten ways a harness loses marks

Once you see the three parts (read a case, call, print a line), the only thing that changes between questions is how many values a case has and what type they are.

Chapters 1 and 2 gave you statements, mutation, if and recursion. This chapter adds the last kind of control flow, loops, and then builds the model you will use to explain every C program from now on: the program location plus the contents of memory. 3.1 The model of computation and the while loop

Definition — how CS 136 models a running program In CS 135 you modelled Racket with substitution (the stepping rules: evaluate the arguments, then replace the call by the body). C is modelled with two complementary mechanisms:
  • Control flow: we track the program location, "where" in the code execution currently is. When a program is run, the location starts at the beginning of main. (In hardware the location is the program counter, the address of the current machine instruction.)
  • Memory: the current contents of every variable (Sections 3.6 to 3.12).
The four kinds of control flow are compound statements (blocks), function calls, conditionals (if) and iteration (loops). Only iteration is new in this chapter.
The while loop 
while (expression) {
  statements      // the body
}
Check the expression. If it is true (non-zero) run the body, then jump back and check the expression again. If it is false, skip past the whole loop. The expression is checked before every pass, including the first one, so the body may run zero times. In CS 136 always use a block {}, even for a one-statement body.
Worked example — counting down 
int i = 5;
while (i > 0) {
  printf("%d\n", i);
  --i;
}
printf("liftoff\n");
Output: 5 4 3 2 1 on separate lines, then liftoff. When i becomes 0 the check i > 0 fails and the location moves to the printf after the loop.
Understand it this way A while is an if that jumps back. Looping is deeply "imperative": the only thing that ever makes the condition change is mutation inside the body. If nothing in the body moves the loop toward the exit, you have written an endless loop.

3.2 Iteration versus recursion, and converting between them

Solving a problem with a loop is called iteration. In recursion the statements are repeated by calling the function again (each call pushes a new stack frame, Section 3.11); in iteration they are repeated by a loop inside one call. The two usually cost about the same time, but iteration uses no extra stack memory, so for very deep repetition (a million steps) iteration is the safe choice. Recursion stays clearer for naturally recursive structures (trees, later in the course). Here is the same function three ways:

// sum_to(k) returns 0 + 1 + ... + k
// requires: k >= 0
int sum_to(int k) {              // simple recursion: work left to do after the call
  assert(k >= 0);
  if (k == 0) {
    return 0;
  }
  return k + sum_to(k - 1);
}
// accumulative recursion
int sum_to_acc(int k, int acc) {
  if (k == 0) {
    return acc;
  }
  return sum_to_acc(k - 1, acc + k);
}

int sum_to(int k) {
  assert(k >= 0);
  return sum_to_acc(k, 0);
}
// iteration (while loop)
int sum_to(int k) {
  assert(k >= 0);
  int acc = 0;          // the accumulator's start value
  while (k != 0) {      // the base case, negated
    acc = acc + k;      // the call's new acc
    k = k - 1;          // the call's new k
  }
  return acc;           // the base case's answer
}
Recipe — accumulative recursion to a loop
  1. Each parameter of the helper becomes a local variable. The accumulator starts at the value the wrapper passed in (0 for sums, 1 for products).
  2. The base-case test, negated, becomes the loop condition: if (k == 0) return acc; becomes while (k != 0).
  3. The argument expressions of the recursive call become assignments: sum_to_acc(k - 1, acc + k) becomes acc = acc + k; k = k - 1;. Every right-hand side must use the old values, so assign the variable that the others depend on last.
  4. After the loop, return the accumulator.
Going the other way (loop to accumulative recursion): the loop variables become parameters, the negated loop condition becomes the base case, the body's updates become the arguments of the recursive call, and a wrapper passes the initial values. Simple recursion that does work after the call (k + sum_to(k - 1)) does not convert directly: rewrite it accumulatively first.
Watch out — the order of the updates fact_acc(n - 1, acc * n) must become acc = acc * n; n = n - 1;. Written the other way round (n = n - 1; acc = acc * n;) the product uses the new n and you get (n-1)!: an off-by-one that passes no test. Other classic conversion slips: starting the accumulator at 0 for a product, using < where the base case needs <=, and forgetting to return acc; after the loop (the function then returns garbage or does not compile).

do ... while

  statements

The body runs first, then the expression is checked at the end of each pass. So the body always runs at least once.

Definition — break break; immediately terminates the innermost enclosing loop; execution continues with the first statement after that loop. It is often paired with a purposely infinite loop while (1). break only terminates loops: it cannot "break out of" an if. Inside nested loops it leaves only the inner loop. 
// read_until_zero() reads integers and prints each one until a 0 is read
//   or the input ends
// effects: reads input, produces output

  while (1) {
    int n = 0;
    if (scanf("%d", &n) != 1 || n == 0) {
      break;                       // leaves the while (1)
    }

  }
}
Definition — continue continue; skips the rest of the current pass through the body and "continues" with the loop. In a while or do...while loop it jumps straight to the condition; in a for loop it first runs the update, then checks the condition (Section 3.4). Everything written below the continue in the body is skipped, including your update statement. 
int n = 0;
while (scanf("%d", &n) == 1) {   // progress happens in the condition itself,
  if (n % 2 == 0) {               // so this continue is safe
    continue;
  }
  printf("%d\n", n);              // only odd numbers get here
}
Watch out — the sum_odd disaster (this cost you marks on Quiz 2) 
// BUGGY: an endless loop for EVERY n
int sum_odd(int n) {
  int total = 0;
  while (n >= 0) {
    if (n % 2 == 0) {
      continue;        // jumps to (n >= 0) with n unchanged
    } else {
      total += n;
      n--;
    }
  }
  return total;
}
For an even n the first pass hits continue and n never changes. For an odd n the loop works until n becomes even, then sticks; and even if it survived that, n == 0 satisfies n >= 0 and is even, so the loop can never exit. Rule: every path through a loop body must move the loop toward its exit. Before you write continue, ask "does my update still run?" Three correct versions (the sum of the first m odd numbers is m*m, so sum_odd(7) is 16 and sum_odd(6) is 9: use that to test): 
// sum_odd(n) returns the sum of the odd integers from 1 up to n
// requires: n > 0
int sum_odd(int n) {              // version 1: no continue, update on every path
  assert(n > 0);
  int total = 0;
  while (n > 0) {
    if (n % 2 == 1) {
      total += n;
    }
    --n;                          // runs whether or not n was odd
  }
  return total;
}

int sum_odd(int n) {              // version 2: a for loop that only visits odd values
  assert(n > 0);
  int total = 0;
  for (int i = 1; i <= n; i += 2) {
    total += i;
  }
  return total;
}

int sum_odd(int n) {              // version 3: continue done right, in a for loop
  assert(n > 0);
  int total = 0;
  for (int i = n; i > 0; --i) {
    if (i % 2 == 0) {
      continue;                   // safe: the for update (--i) still runs
    }
    total += i;
  }
  return total;
}

3.4 for loops

A for loop is a condensed while loop 
setup;
while (expression) {
  body
  update;
}
for (setup; expression; update) {
  body
}
Order of execution: setup once; then check the expression; if true run the body, then the update, then check again. The update runs after the body, never before the first pass. Any of the three parts may be omitted; an omitted expression counts as always true, so for (;;) is an infinite loop.
The four counting idioms (memorize the first and last values) 
for (int i = 0; i < n; ++i) { ... }       // 0, 1, ..., n-1    n passes (the array idiom)
for (int i = 1; i <= n; ++i) { ... }      // 1, 2, ..., n      n passes
for (int i = n - 1; i >= 0; --i) { ... }  // n-1, ..., 1, 0    n passes
for (int i = n; i >= 1; --i) { ... }      // n, ..., 2, 1      n passes
Off-by-one check: write down the first value and the last value the body sees. An inclusive range a..b with step 1 gives b - a + 1 passes. < versus <= is the most common error on loop questions; when unsure, rewrite the for as a while and trace two passes.
Worked example — the same countdown both ways 
int i = 5;
while (i > 0) {
  printf("%d\n", i);
  --i;
}
for (int i = 5; i > 0; --i) {
  printf("%d\n", i);
}
Three lines instead of five, and the loop variable lives only inside the loop.
Rules — scope, continue and what is banned
  • Loop-scoped variables (C99): a variable defined in the setup (for (int i = 0; ...)) exists only inside the loop. After the loop, i is out of scope: using it is a compile error, and you may define a new int i for the next loop. If you need the final value after the loop, define the variable before the loop instead.
  • continue in a for loop runs the update first. This is the one place a for and its while translation behave differently: in the while version a continue jumps over the update at the bottom of the body.
  • Banned in CS 136: the comma operator (for (i = 0, j = n; ...)), switch, goto. Also avoid changing the loop variable inside a for body: legal, but it defeats the point of the idiom.
Watch out — the stray semicolon 
int count = 0;
for (int i = 0; i < 10; ++i);   // <-- this semicolon IS the (empty) body
{
  ++count;                       // an ordinary block, runs once
}
printf("%d\n", count);           // prints 1, not 10
The same thing happens with while (i < n); which is usually an endless loop. Questions love this one.

3.5 Printing patterns with nested loops (assignment A02 style)

Rules for shape-printing questions
  • Print a newline after every line, including the last one. Never print an extra blank line.
  • No trailing spaces: print leading spaces, then the characters, then \n.
  • Think of each line as a formula of its row number: how many leading spaces, how many of each character. Check the first row, a middle row and the last row by hand before coding.
  • Split the work into helper functions: a print_chars(c, n) helper makes every shape a few lines long.
Worked example — a bordered rectangle and a right-aligned triangle 
// print_chars(c, n) prints the character c n times (no newline)
// requires: n >= 0
// effects: produces output
void print_chars(char c, int n) {
  assert(n >= 0);
  for (int i = 0; i < n; ++i) {
    printf("%c", c);
  }
}

// draw_border(width, height, border_char, fill_char) prints a rectangle of
//   width x height characters whose edge is border_char and whose inside is fill_char
// requires: width >= 3, height >= 3
// effects: produces output
void draw_border(int width, int height, char border_char, char fill_char) {
  assert(width >= 3);
  assert(height >= 3);
  for (int row = 0; row < height; ++row) {
    for (int col = 0; col < width; ++col) {
      if (row == 0 || row == height - 1 || col == 0 || col == width - 1) {
        printf("%c", border_char);
      } else {
        printf("%c", fill_char);
      }
    }
    printf("\n");                 // after every row, including the last
  }
}

// draw_triangle(size, c) prints a right-aligned triangle of c's with size rows
// requires: size >= 1
// effects: produces output
void draw_triangle(int size, char c) {
  assert(size >= 1);
  for (int row = 1; row <= size; ++row) {
    print_chars(' ', size - row);   // leading spaces shrink
    print_chars(c, row);            // characters grow
    printf("\n");
  }
}

3.6 Memory, variables and sizeof

Definitions — bits, bytes, addresses A bit stores 0 or 1. A byte is 8 bits (256 possible states) and is the smallest unit of memory you can access. Every byte has an address, its position in memory, usually written in hex: with 1 MB of memory the first byte is at 0x0 and the last at 0xFFFFF (decimal 1048575, which is 2 to the power 20, minus 1). Think of memory as a row of numbered mailboxes, one byte each.
Definition — what a variable definition does For int n = 0; C (1) reserves 4 consecutive bytes, say 0x5000 to 0x5003, (2) keeps track of the starting address 0x5000 under the name n, and (3) stores the initial value there. In CS 135 a variable was a name for a value; in C a variable is a name for a location. When n appears in an expression, C fetches the contents at its address.

3.7 Integer limits and overflow

Definition — INT_MIN, INT_MAX and overflow With 32 bits an int can hold the values from INT_MIN = -231 = -2,147,483,648 to INT_MAX = 231 - 1 = 2,147,483,647. Both constants come from cs136.h. Producing a value outside this range is overflow, and the value of an int after overflow is undefined: never assume it "wraps around", "doubles" or "stays the same".
Watch out — the quiz question int x = INT_MAX; x = 2 * x; is undefined behaviour. It is not a compile error (the compiler cannot know the value), and in a real environment you would get a garbage-looking number; the edX environment is configured to stop with an error. Likewise INT_MAX + 1 is undefined, not INT_MIN. Racket never had this problem because its numbers grow to any size; C uses a fixed 4 bytes.
Worked example — when do everyday computations overflow? 12! = 479,001,600 fits in an int; 13! = 6,227,020,800 does not, so a factorial function is only correct for n <= 12. Squaring any n above 46,340 overflows (46,3412 is just over INT_MAX). Sometimes reordering operations avoids it: for non-negative a <= b, a + (b - a) / 2 is the midpoint without the possibly-overflowing sum (a + b) / 2.

Definition — char A char is a 1-byte integer type (256 values, -128 to 127 in our environment). It is rarely used for arithmetic; it is used to store characters, which the ASCII standard maps to small integers. In C a character in single quotes, such as 'a', is just another way of writing the integer 97. Double quotes make a string (an array of characters, Chapter 5): "a" is not 'a'.

// is_lowercase(c) returns true if c is a lowercase letter, false otherwise
bool is_lowercase(char c) {
  return (c >= 'a') && (c <= 'z');

// to_uppercase(c) returns the uppercase version of the lowercase letter c
// requires: c is a lowercase letter
char to_uppercase(char c) {
  assert(is_lowercase(c));
  return c - 'a' + 'A';          // 'q' - 'a' is 16, and 16 + 'A' is 'Q'
}

// digit_value(c) returns the numeric value of the digit character c
// requires: c is one of '0' ... '9'
int digit_value(char c) {
  assert(c >= '0' && c <= '9');
  return c - '0';                // '7' - '0' is 55 - 48 = 7
}
Write 'a', not 97: the compiler translates it for you and the reader sees what you meant. 'a' + 1 is the integer 98, which "%c" displays as b.
Reading characters: "%c" versus " %c" Every keystroke is a character, including spaces and newlines. scanf("%c", &c) reads the next character whatever it is; scanf(" %c", &c) (note the leading space) skips whitespace first and reads the next non-whitespace character. Reading an int with "%d" always skips leading whitespace. The return value is 1 on success, so while (scanf("%c", &c) == 1) { ... } processes a whole input, whitespace included. 
// count_letters() reads all input and returns the number of lowercase letters
// effects: reads input
int count_letters(void) {
  int count = 0;
  char c = 0;
  while (scanf("%c", &c) == 1) {
    if (is_lowercase(c)) {
      ++count;
    }
  }
  return count;
}
Symbols and floats, briefly C has no Racket-style symbol type. Use const int constants with ALL_CAPS names and arbitrary values (const int RED = 1;) to avoid magic numbers; C's enum exists but is not covered. The float and double types are inexact (like #i numbers in Racket) and suffer precision errors; do not use them in CS 136 unless a question says so.

3.9 Structures

Definition syntax 
struct posn {
  int x;
  int y;
};                                    // <-- do NOT forget this semicolon

struct posn p = {3, 4};               // fields in order: x = 3, y = 4
struct posn q = {.y = 4, .x = 3};     // C99 designated initializers (any order)
struct posn r = {.x = 3};             // omitted fields are 0: r.y is 0
trace_int(p.x);                       // the . operator selects a field
The type is struct posn, not posn. Because C is statically typed, every field has a declared type. The definition of the structure reserves no memory; memory is reserved only when a variable of that type is defined.
Rules — mutation, copying, equality, printing
  • Mutate a field: p.x = 7;
  • Copy the whole thing: p = q; copies every field; afterwards changing q does not affect p.
  • No braces after the definition: p = {5, 6}; is invalid; the braces are initialization syntax only. Assign each field, or define a new struct posn and assign it.
  • No ==: the equality operator does not work on structures. Write your own: bool posn_equal(struct posn a, struct posn b) { return (a.x == b.x) && (a.y == b.y); }
  • No printf of a struct: print each field, printf("(%d, %d)\n", p.x, p.y);
Watch out — sizeof a struct sizeof(struct posn) is at least the sum of the field sizes (8 here) but may be larger: C may insert padding to align fields, and the amount can depend on the field order. A struct { char c; int n; } typically occupies 8 bytes, not 5. On an exam say "at least the sum, possibly more because of alignment; you must use sizeof", and never add the fields up as if that were the answer.

3.11 Function calls and the call stack

Definition — stack, call stack, stack frame A stack holds items so that only the top one is accessible: items are pushed onto the top and popped off the top. Every function call pushes a stack frame; when the function returns, its frame is popped and control goes back to the function now on top. The call stack therefore shows the history of calls that led to the current moment, bottom (main) to top (the running function). Each frame contains exactly three kinds of things:
  1. the argument values (copies: this is pass by value);
  2. all local variables that appear anywhere in the function block, including inner blocks and loop bodies, and including ones whose definition has not been reached yet (shown as ???);
  3. the return address: the program location in the calling function to go back to.
Worked example — the call stack as history

Definition — the return address When a return is reached, C must know where the program location was when this function was called. That location is the return address. In CS 136 we write it as the calling function's name and the line number of the call: return address: main:12. The operating system calls main, so main's return address is OS. (The Quiz 3 marker also accepted the form r/a: main, line 7.) The return address has nothing to do with the return statements inside the called function; a void function with no return still has exactly one return address in its frame.
Rules — what happens on a call and on a return Calling a function:
  1. a stack frame is created (pushed onto the stack);
  2. the current program location is stored in the frame as the return address;
  3. a copy of each argument is placed in the frame (the arguments must already be values);
  4. the program location jumps to the start of the function;
  5. each local variable gets its initial value when its definition is reached (before that it is ???).
Returning: the program location changes back to the return address, and the frame is popped; everything in it "disappears". The returned value is held in temporary storage we do not model. Because the function only ever had copies of the arguments, it cannot change the caller's variables (that changes in Chapter 4 with pointers).

CHAPTER 4

Pointers

A pointer is a variable whose value is a memory address. Chapter 3 gave you the memory model (frames, addresses, pass by value); this chapter gives you the two operators that expose it, & and *, and the one thing you cannot do without them: let a function change a variable that lives in another frame. On the midterm this shows up as fill-in-the-blank tracing (u = v vs *u = *v), stack diagrams with addr_1 labels, "which line is a compile error", and at least one full function with pointer parameters plus a main that tests it.

The one picture to keep in your head Memory is a row of numbered boxes (Chapter 3). A variable is a name for a box. &i asks "what is the number of i's box?" and *p says "take the number stored in p, go to that box, and use what is inside it". A pointer is just a box whose content is the number of another box. In diagrams we draw that content as an arrow, because the actual number is irrelevant; on paper we name it addr_1.

4.1 The address operator and pointer definitions

Definition — address operator & and the %p specifier

The address operator & produces the location (starting address) of an identifier in memory. The printf specifier %p prints an address in hex. You have already used & every time you wrote scanf("%d", &x).

#include "cs136.h"

int g = 42;

int main(void) {
  int i = 7;
  printf("%p\n", &i);   // an address in the stack, e.g. 0x7ffc...
  printf("%p\n", &g);   // an address in global data
}

The exact numbers change from run to run and are never asked for. What is asked: the type of &i is int *, read "int pointer".

Definition — pointer, pointer type

A pointer is a variable that stores a memory address. To define one, put a star before the name. The type of a pointer is the type of the data it points at, followed by *; there is a pointer type for every type.

int i = 42;
int *pi = &i;            // type int *          : "pointer to an int"
char c = 'a';
char *pc = &c;           // type char *         : "pointer to a char"
struct posn p = {1, 2};
struct posn *pp = &p;    // type struct posn *  : "pointer to a struct posn"
Definition syntax: type *name = initial_address;
The * is part of the definition, not of the name. The variable in int *q = &i; is called q, not *q, and that line means exactly the same as the two lines int *q = NULL; then q = &i;.
Watch out — where the star belongs

C ignores the whitespace, so int *p, int * p and int* p are identical. CS 136 (and the textbook) use style A, int *p, because the star binds to the name, which matters the moment two variables share a line:

int i = 42, j = 23;
int *p1 = &i, *p2 = &j;   // VALID: p1 and p2 are both int pointers
int * p1 = &i, p2 = &j;   // INVALID: p2 is a plain int, and &j is not an int

(Defining two variables on one line is bad style here anyway. Know the rule for exam questions; write one definition per line in your own code.)

Pointers to pointers

Can a pointer point at itself? No: a variable of type int * may only hold the address of an int, and the pointer itself is not an int. Assigning p = &p; is a type error (the right side has type int **). What you can do is define a pointer to a pointer:

int i = 42;
int *p = &i;
int **pp = &p;      // "pointer to a pointer to an int"
trace_int(*pp == p);  // 1: *pp is the value of p, which is &i
trace_int(**pp);      // 42: follow both arrows

Any depth is legal, but more than two stars is rare. (A void * can point at anything, including itself; that is the last module of the course, not this one.)

A pointer is a variable too

Because p is a variable, it has its own address, &p, which is different from its value &i. Two questions keep these apart: "what is in p?" (the address of i) and "where is p?" (&p). In a memory diagram we rarely care about the number stored in a pointer, so we draw an arrow from the pointer's box to the target box, or on paper write addr_1 in the pointer and tag the target [addr_1].

Definition — NULL

NULL is a special pointer value meaning "points at nothing". Assign it when the target is not yet known or has become invalid: int *p = NULL; is good style, int *p; (uninitialized) earns a warning in edX and a garbage address in real life. NULL is false in a Boolean context (like 0), so these pairs are equivalent and both are good style:

if (p != NULL) { ... }     if (p) { ... }
if (p == NULL) { ... }     if (!p) { ... }

Like any variable, a pointer can be re-assigned as often as you like: to &j, back to NULL, then to &i.

Definition — sizeof a pointer In our 64-bit edX environment, sizeof of any pointer is 8 bytes, whatever it points at: sizeof(int *), sizeof(char *) and sizeof(struct posn *) are all 8, even though an int is 4 bytes, a char is 1 and a struct may be large. A pointer stores an address, and addresses are 64 bits long. Memorize the triple: char 1, int 4, pointer 8.

4.2 Dereferencing, the arrow operator, and aliasing

Definition — dereference operator *

The dereference (or indirection) operator * is the inverse of &: *p produces the value of what p points at, and *p = ... changes what p points at. *&i is simply i (take the address, then follow it), and so is *&*&i.

int i = 42;
int *p = &i;
trace_int(*p);     // 42
*p = 43;           // mutates i through p
trace_int(i);      // 43
trace_int(*&i);    // 43: &i is an address, * follows it back to i
Watch out — three things that are errors or crashes
  • &*i when i is an int is a compile error: *i tries to dereference something that is not a pointer. (Quiz 3 asked exactly this: *&temp is 9, &*temp is an error.) &*p for a pointer p is legal and equals p.
  • Dereferencing NULL compiles but crashes the program (edX reports an error; real systems say "segmentation fault"). It does not produce 0. This is why pointer parameters get assert(p).
  • Dereferencing an uninitialized pointer reads or writes a random box in memory. Initialize to NULL or to a real address.

Definition — the arrow operator ->

The structure selector . has higher precedence than *, so *ptr.field is parsed as *(ptr.field), which is an error (a pointer has no fields). You must write (*ptr).field. The arrow operator does the dereference and the selection in one step: ptr->field is exactly (*ptr).field. Use the arrow; it is the course's preferred form.

struct posn p = {3, 4};

Aliasing: p = q versus *p = *q

Aliasing occurs when the same box can be reached through more than one name: after int *ptr = &score;, score and *ptr are aliases of each other, and changing either changes both. Two assignments look alike and do completely different things:

StatementWhat changesIn words
p = q;the pointer p"make p point at whatever q points at" (p's old target is untouched)

Worked example — the Quiz 3 fill-in-the-blanks, done slowly 
int a = 3;
int b = 7;
int *u = &a;
int *v = &b;

Case 1: run u = v;. The value stored in u becomes the value stored in v, which is &b. So u holds &b, *u is 7, and a is still 3 (nobody wrote to a's box).

Case 2: start again from the setup and run *u = *v;. *v is 7; it is stored into the box u points at, which is a. So u still holds &a, *u is 7, and a is now 7. The variable a changed even though its name never appeared in the statement; that is the whole danger and the whole power of aliasing.

A reliable method on paper: draw the four boxes, draw arrows for u and v, then for each statement ask "does the left side have a star?" No star: an arrow moves. Star: a value is written into a box at the end of an arrow.

4.3 Mutation and parameters: pass by value, emulated pass by reference

Definition — pass by value (what C always does)

When a function is called, a copy of each argument value is placed in the new stack frame. The function can change its copy; the caller's variable is untouched. There is no way around this rule.

// inc(x) returns x + 1
int inc(int x) {
  x += 1;          // line 3: changes only inc's own copy
  return x;
}

int main(void) {
  int x = 5;
  inc(x);          // line 9: the return value is discarded
  trace_int(x);    // 5, not 6
}

Definition — emulating pass by reference

Some languages let a function change the caller's variable ("pass by reference"). C emulates it: pass the address of the variable, and let the function write through the pointer. Technically this is still pass by value (the address is copied), which is exactly why it works: the copy of the address still points at the original box.

// inc(p) adds 1 to the integer that p points at
// requires: p is a valid pointer
// effects: modifies *p
void inc(int *p) {
  assert(p);       // every pointer parameter that must be valid gets an assert
  *p += 1;         // line 6
}

int main(void) {
  int x = 5;
  inc(&x);         // line 11: "pass a pointer to x"
  assert(x == 6);
}

Watch out — (*p)++ needs its parentheses

Postfix ++ binds tighter than *, so *p++ means *(p++): it increments the pointer (moves it to the next box, Chapter 5) and leaves the target alone. To add one to the target write *p += 1; or (*p)++; or ++(*p);. The quiz-3 bump function used (*q)++; on purpose. A second classic: writing p += 1; inside inc, which moves the pointer instead of changing the value.

Understand it this way — scanf was pointers all along scanf("%d", &x) has the same shape as inc(&x): it receives an int * so that it can store the value it reads into your variable. That is why forgetting the & is so bad: scanf("%d", x) passes the value of x as if it were an address, and scanf writes the input into a random box. The same mechanism also explains why scanf can "return two things": the count comes back through return, the value read comes back through the pointer.
Definition — the four side effects you must document
  1. produce output (printf)  // effects: produces output
  2. read input (scanf)  // effects: reads input
  3. mutate a global variable  // effects: modifies counter (banned in assignments unless allowed)
  4. mutate a variable through a pointer parameter  // effects: modifies *p

Write "may modify" when the mutation is conditional. Mutating a local variable or a parameter's own copy is not a side effect. assert and tracing are never listed under effects.

Worked example — swap, documented the way markers want it 
// swap(px, py) exchanges the values of *px and *py
// requires: px and py are valid pointers
// effects: modifies *px and *py
void swap(int *px, int *py) {
  assert(px);
  assert(py);
  const int temp = *px;
  *px = *py;
  *py = temp;
}

int main(void) {
  int a = 3;
  int b = 4;
  swap(&a, &b);
  assert(a == 4);
  assert(b == 3);
}

Notice the order inside main: define the variables (initialized), call with their addresses, assert each one. In Racket there was no observable difference between pass by value and pass by reference because nothing was ever mutated; in C the difference is the whole point.

Returning an address

A function may return a pointer. The rule that decides whether it is legal is about whose frame the target lives in.

// ptr_to_max(a, b) returns a pointer to the larger of *a and *b
// requires: a and b are valid pointers
int *ptr_to_max(int *a, int *b) {
  assert(a);
  assert(b);
  if (*a >= *b) {
    return a;      // fine: a points into the CALLER's memory, which survives
  }
  return b;
}

int *fresh_counter(void) {
  int tally = 100;
  return &tally;   // WRONG: tally is in fresh_counter's frame, which is popped
}                  //        the moment the function returns (edX warns)
Watch out A function must never return the address of a variable (or parameter) in its own stack frame. When the function returns, the frame is popped and that memory is considered invalid; whatever the caller reads through the pointer is garbage. Quiz 3 asked this about fresh_counter: it compiles, it is just wrong. Returning a pointer you were given, or a pointer to global data, is fine.

4.4 "Returning" more than one value

A C function returns exactly one value. When you need two or more results, or a result plus a success flag, pass the addresses of the output variables and write through them. The return value is then free to report status.

Worked example — divide with a status flag 
// divide(a, b, quot, rem) stores a / b in *quot and a % b in *rem and
//   returns true; if b is zero it returns false and changes nothing
// requires: quot and rem are valid pointers
// effects: may modify *quot and *rem
bool divide(int a, int b, int *quot, int *rem) {
  assert(quot);
  assert(rem);
  if (b == 0) {
    return false;
  }
  *quot = a / b;
  *rem = a % b;
  return true;
}

int main(void) {
  int quot = 0;
  int rem = 0;
  assert(divide(17, 5, &quot, &rem));
  assert(quot == 3);
  assert(rem == 2);
  assert(!divide(17, 0, &quot, &rem));
  assert(quot == 3);   // untouched by the failed call
  assert(rem == 2);
}

Either convention (true means success, or true means error, as in the course's Example 4.3.1) is acceptable as long as the purpose says which. Library functions often use sentinel return values instead: -1, NULL, or EOF from scanf.

The main-test template for a function with pointer outputs (this is where Quiz 3 marks went) 
int main(void) {
  int lo = 0;                 // 1. define every output variable, initialized
  int hi = 0;
  min_max(8, 3, &lo, &hi);    // 2. call with the ADDRESSES of those variables
  assert(lo == 3);            // 3. one assert per output, against the expected value
  assert(hi == 8);
}
You cannot pass &a to a function if a was never defined, and an assert that only checks b == 8 is worth nothing if b does not exist. Three lines before the call, one per output after it.

4.5 Passing structures by pointer

Passing a struct by value copies every field into the new frame. For a large struct that is slow, so it is standard practice to pass the address of a structure. There are two different reasons to do it, and your documentation must make clear which one applies:

  • to avoid copying, when the function only reads the struct: mark the parameter const;
  • to mutate the caller's struct: no const, and an effects: line.
struct posn {
  int x;
  int y;
};

// sqr_dist(p1, p2) returns the square of the distance between *p1 and *p2
// requires: p1 and p2 are valid pointers
int sqr_dist(const struct posn *p1, const struct posn *p2) {
  assert(p1);
  assert(p2);
  const int xdist = p1->x - p2->x;
  const int ydist = p1->y - p2->y;
  return xdist * xdist + ydist * ydist;
}

// scale(p, f) scales the posn *p by f
// requires: p is a valid pointer
// effects: modifies *p
void scale(struct posn *p, int f) {
  assert(p);
  p->x *= f;
  p->y *= f;
}

int main(void) {
  struct posn a = {1, 2};
  struct posn b = {4, 6};
  assert(sqr_dist(&a, &b) == 25);
  scale(&a, 3);
  assert(a.x == 3);
  assert(a.y == 6);
}

In the purpose it is fine to write "scales the posn *p" or even just "scales p"; everyone understands that p stands for the structure. Documenting the absence of a side effect is awkward, which is what const is for: it says "no mutation here" and the compiler enforces it.

4.6 const and pointers

Definition — const pointer forms

Adding const to the front of a pointer definition protects the destination: the target cannot be changed through this pointer (the variable itself may still be changed directly, if it is mutable). The pointer variable itself stays mutable unless you put const after the star.

The rule: const applies to the thing on its left, unless it is the first word, in which case it applies to the thing on its right. So int const *p is the same as const int *p (both forms are legal; the course writes const int). Definition — const parameters

On a pointer parameter, const is good style whenever the function does not mutate the target: int sum(const int *p) communicates and enforces "I only read". Callers may still pass the address of a mutable variable.

On a plain value parameter, const means the function's own copy cannot be changed: in int f(const int x) { x = 3; } the assignment is a compile error. It does not require the argument to be constant, because the argument is copied anyway; f(y) with a mutable y is fine.

Definition — the function-design ladder (prefer the top)
  1. Pure function: no side effects, depends only on its arguments (and global constants, which are fine).
  2. I/O side effects only (reads input or prints), no mutation of anything outside the function.
  3. Mutation through pointer parameters: when the caller must get something back, this is the sanctioned way.
  4. Dependency on a global mutable variable: impure even with no side effect; avoid.
  5. Mutating global data: only when absolutely necessary, and in CS 136 only when an assignment explicitly allows it.

4.7 Function pointers

Definition — function pointer

Functions are not first-class values in C (you cannot create one while the program runs), but pointers to functions are values. A function pointer stores the starting address of a function, which is an address in the code section of memory. Its type includes the return type and every parameter type.

Syntax: return_type (*fpname)(param1_type, param2_type, ...) 
int my_add(int a, int b) {
  return a + b;
}

int my_sub(int a, int b) {
  return a - b;
}

int main(void) {
  int (*fp)(int, int) = NULL;   // fp: pointer to a function (int, int) -> int
  fp = my_add;                   // &my_add also works; the plain name is usual
  trace_int(fp(2, 3));           // 5
  fp = my_sub;
  trace_int(fp(2, 3));           // -1
}
The parentheses around *fp are required: int *fp(int, int) declares a function that returns an int *. A function pointer can only point at a function that already exists. You will not be asked to recall this syntax from memory on the exam, but when it is given you must be able to assign to it, call it, and pass it.
Worked example — passing a function to a function 
// sqr(x) returns x squared
int sqr(int x) {
  return x * x;
}

// io_apply(f) reads integers until there are no more and prints f(x)
//   on its own line for each integer x read
// requires: f is a valid function pointer
// effects: reads input, produces output
void io_apply(int (*f)(int)) {
  assert(f);
  int x = 0;
  while (scanf("%d", &x) == 1) {
    printf("%d\n", f(x));
  }
}

  io_apply(sqr);      // input 2 3 4 prints 4, 9, 16 on separate lines

CHAPTER 5

Arrays, Pointer Arithmetic and Strings

C has exactly two built-in compound types: structures and arrays. An array is a fixed number of same-type values sitting side by side in memory, and a string is nothing more than a char array that ends with a null character. On the midterm this chapter appears as "write find_max_index with a test harness", "what is p2 - p1", "show the array after this strcat", and "which of these definitions is invalid". Most lost marks here come from hand-written code with missing element types, missing length parameters, missing terminators and missing returns.

Plain-English warm-up: three facts that run the whole chapter
  1. An array is a row of numbered mailboxes, numbered from 0. int a[6] gives you six boxes a[0] to a[5]. There is no a[6], and C will not stop you from opening it anyway.
  2. The array's name is the address of box 0. Write a on its own and C hands over &a[0]. That is why a function receiving an array only gets an address, cannot tell how long the array is, and can change the caller's boxes.
  3. A string is a char array with a '\0' at the end, and every string function walks forward until it finds that zero. Forget the zero and printf, strlen and friends keep walking into whatever memory comes next.

5.1 Arrays

Definition — array An array is a data structure that holds a fixed number of elements, all of the same type. The number of elements is the length and must be known when the array is defined. Each element is reached through its index, counting from 0: for int a[6] the first element is a[0] and the last is a[5]. An element behaves exactly like a variable (read it, assign to it, pass it to a function), and the index can be any int expression: a[i + 1], a[2 * k], even a[a[0]].
#include "cs136.h"

int main(void) {
  int a[6] = {4, 8, 15, 16, 23, 42};   // length 6, indices 0..5
  trace_int(a[0]);                      // 4
  a[1] = a[0] + a[5];                   // a[1] is now 46
  a[a[0] - 4] = 0;                      // index expression: a[0] becomes 0
  int sum = 0;
  for (int i = 0; i < 6; ++i) {         // THE array loop: 0 up to length - 1
    sum += a[i];
  }
  trace_int(sum);                       // 0 + 46 + 15 + 16 + 23 + 42 = 142
}
Understand it this way Arrays and loops are a matched pair. The loop counter is the index, so "do something to every element" is always for (int i = 0; i < len; ++i) { ... a[i] ... }. The condition is < len, never <= len: index len is one past the end.

Uninitialized arrays

Same rule as single variables. A global array (defined outside every function) is zero-filled automatically. A local array (on the stack) that is not initialized is full of arbitrary leftover values. Always initialize: int a[5] = {0}; costs nothing and removes a whole class of bugs.

C does not remember the length

Rule — you track the length yourself Nothing in the array stores its length. Keep it in a constant defined after the array, and pass it alongside the array to every function that needs it: 
int a[6] = {4, 8, 15, 16, 23, 42};
const int a_len = 6;      // defined AFTER the array, in CS 136
Things you will see in the notes but must not use in this course: size_t (unsigned, so i >= 0 loops never end when counting down), #define A_LEN 6 macros, variable length arrays int a[n]; (banned), and the sizeof(a) / sizeof(a[0]) trick (only works where the array was defined, never inside a function that received it). Define arrays with a literal number and carry an int length.

Arrays in memory

Elements are contiguous: each one sits immediately after the previous one, so the whole array occupies one solid block of length × element-size bytes. The address of the array is the address of its first element.

int a[6] = {4, 8, 15, 16, 23, 42};          (each int is 4 bytes)

*a  ==  a[0] ==  4

Definition — the array identifier "decays" to an address An array has no single "value". When the name a appears by itself in an expression it evaluates to the address of the first element, &a[0]. So a, &a and &a[0] all print the same address with %p, and *a is the same as a[0]. They do not all have the same type (&a is "pointer to an array of 6 ints"), which is why &a is the wrong thing to pass to a function expecting int a[].

Passing arrays to functions

#include "cs136.h"

// sum_array(a, len) returns the sum of the first len elements of a
// requires: len >= 0, a has at least len elements [not asserted]
int sum_array(const int a[], int len) {
  assert(a != NULL);
  assert(len >= 0);
  int sum = 0;
  for (int i = 0; i < len; ++i) {
    sum += a[i];
  }
  return sum;
}

// array_negate(a, len) negates every one of the first len elements of a
// requires: len >= 0, a has at least len elements [not asserted]
// effects: modifies a
void array_negate(int a[], int len) {
  assert(a != NULL);
  assert(len >= 0);
  for (int i = 0; i < len; ++i) {
    a[i] = -a[i];
  }
}

int main(void) {
  int my_array[6] = {4, 8, 15, 16, 23, 42};
  assert(sum_array(my_array, 6) == 108);     // pass my_array, NOT &my_array
  array_negate(my_array, 6);                 // the caller's array changes
  assert(my_array[0] == -4);
  assert(my_array[5] == -42);
  assert(sum_array(my_array, 6) == -108);
}
  • Only the address is copied into the stack frame (8 bytes), never the elements. That is efficient, and it means the function can mutate the caller's array through that address.
  • The function has no way to know the length, so the length is a separate int parameter. It also has no way to check the length, so the requirement is documented [not asserted]. What you can assert: assert(a != NULL); and a condition on len.
  • Write const int a[] when the function does not modify the array. It stops accidental mutation (the compiler refuses a[i] = ...) and tells the reader their array is safe. Leave const off only when mutation is the point.
  • int a[] and int *a mean the same thing in a parameter list. A length written inside the brackets, as in void calendar(int days_per_month[12]), is ignored: any length can be passed.
  • Call with the bare name: sum_array(my_array, 6). Never sum_array(&my_array, 6) (wrong type) and never sum_array(my_array[], 6) (not C).
Worked example — find_max_index, exactly as a marker wants it

Write find_max_index, which takes a read-only array of integers arr and its length len and returns the index of the first occurrence of the maximum element. For {3, 7, 2, 7} it returns 1. Include full documentation and a main with a test and an assert.

#include "cs136.h"

// find_max_index(arr, len) returns the index of the first occurrence of the
//   largest element of arr
// requires: arr != NULL, len > 0
//           arr has at least len elements [not asserted]
int find_max_index(const int arr[], int len) {
  assert(arr != NULL);
  assert(len > 0);
  int max_index = 0;
  for (int i = 1; i < len; ++i) {
    if (arr[i] > arr[max_index]) {    // strictly greater keeps the FIRST max
      max_index = i;
    }
  }
  return max_index;
}

int main(void) {
  int a[4] = {3, 7, 2, 7};
  assert(find_max_index(a, 4) == 1);
  int b[1] = {-5};
  assert(find_max_index(b, 1) == 0);
  int c[5] = {1, 2, 3, 4, 5};
  assert(find_max_index(c, 5) == 4);
}
Every line here earns or protects a mark: the element type int in const int arr[], the two asserts inside the function, int i declared in the for, the loop bound i < len, the > (not >=) so ties keep the first index, the return, and a main whose array has a type and is passed as a, not &a.

Oversized arrays

Because the length must be fixed in advance, a common pre-dynamic-memory trick is an array that is "big enough", plus a count of how much of it is actually in use. Bundle the three related values in a structure, and always pass that structure by pointer, otherwise every call copies the entire array into the stack frame.

struct oversized_array {
  int data[10];     // room for up to 10 ints
  int len;          // how many are actually stored (0..maxlen)
  int maxlen;       // 10
};

// bad(oa) ... copies all 48 bytes of oa into the frame on every call
int bad(struct oversized_array oa) { return oa.len; }

// good(oa) ... copies only an 8-byte address
int good(const struct oversized_array *oa) { return oa->len; }

int main(void) {
  struct oversized_array oa = {.len = 0, .maxlen = 10};   // data zero-filled
  int n = 0;
  while (oa.len < oa.maxlen && scanf("%d", &n) == 1) {
    oa.data[oa.len] = n;     // store in the next free slot
    oa.len += 1;             // then count it (one side effect per statement)
  }
}

Two-dimensional data in a one-dimensional array

A table with NUMROWS rows and NUMCOLS columns is stored row after row in a 1D array of length NUMROWS * NUMCOLS:
element (row, col) is data[row * NUMCOLS + col]
int data[6] = {1, 2, 3, 7, 8, 9}; is the 2 × 3 table with rows 1 2 3 and 7 8 9; (row 1, col 2) is data[1 * 3 + 2] = data[5] = 9.

C does have real multi-dimensional arrays (int t[2][3]) but they are not covered in CS 136; the mapping formula is what you are expected to use.

5.2 Pointer arithmetic

The rules (for a pointer p and an integer i)
p + i is the address p + i * sizeof(*p): it moves i elements, not i bytes  ·  p - i likewise
++p is p = p + 1 (only for a mutable pointer)  ·  you cannot add two pointers
p - q (same pointer type) is the number of elements between them: if p = q + i then p - q is i
Pointers of the same type can be compared: < <= == != >= >
All of this is only meaningful inside one array (the C standard says so).
Understand it this way The pointer knows the size of what it points at, and it counts in those units. For an int *p, p + 1 is 4 bytes further on; for a char *c, c + 1 is 1 byte on; for a struct posn *q it is sizeof(struct posn) bytes on. Likewise p2 - p1 answers "how many elements apart", and the raw byte distance divided by the element size.
int values[5] = {10, 20, 30, 40, 50};
int *p1 = &values[1];       // points at 20
int *p2 = &values[4];       // points at 50
trace_int(p2 - p1);         // 3   (three elements apart: 12 bytes / 4)
trace_int(p2[-2]);          // 30  (p2[-2] is *(p2 - 2), which is values[2])
trace_int(*(p1 + 2));       // 40  (values[3])
++p1;                       // p1 now points at values[2]
trace_int(*p1);             // 30
trace_int(p1 < p2);         // 1
char *c1 = (char *) p1;     // just to show scaling: for a char pointer...
trace_ptr(c1 + 1);          // ...this is only 1 byte past c1, not 4
Definition — [] is pointer arithmetic in disguise a[i] means *(a + i), and &a[i] means a + i. That is the whole reason arrays and pointers look alike: the square brackets are an operator that adds and dereferences. It works on any pointer, which is why p2[-2] above is legal and means *(p2 - 2).
Watch out — no bounds checking, ever For int a[6], C translates a[6] or a[-1] or a[1000000] into *(a + ...) and happily reads or writes whatever is there: another variable, a return address, or memory that makes the program crash. Nothing warns you. Off-by-one loop bounds (<= instead of <) are the usual way to get here, and this is the most criticized feature of C.

Array pointer notation

Any loop over an array can be written with a moving pointer instead of an index. Both styles are expected on the exam; the pointer style is the traditional one for string functions.

// sum_array(a, len) returns the sum of the first len elements of a
// requires: len >= 0, a has at least len elements [not asserted]
int sum_array(const int *a, int len) {
  assert(a != NULL);
  assert(len >= 0);
  int sum = 0;
  const int *p = a;              // p may move; *p may not be changed through p
  while (p < a + len) {          // a + len is one past the last element
    sum += *p;
    ++p;
  }
  return sum;
}

// array_map(f, a, len) replaces each a[i] with f(a[i])
// requires: a has at least len elements, len >= 0 [not asserted]
// effects: modifies a
void array_map(int (*f)(int), int a[], int len) {
  assert(a != NULL);
  assert(len >= 0);
  for (int i = 0; i < len; ++i) {
    a[i] = f(a[i]);
  }
}

Note const int *p: the pointer itself is mutable (++p is fine) but the int it points at is not (*p = 0 is an error). int sum_array(const int a[], int len) and int sum_array(const int *a, int len) are identical declarations to C. array_map is the imperative cousin of Racket's map: it mutates the existing array instead of producing a new one.

5.3 Strings

Definition — C string There is no string type in C. By convention a string is an array of char terminated by a null character. The null character (null terminator) is a char with value 0, written '\0' to make the intent clear. Three things that look alike and are not: '\0' is 0, '0' is the digit character with value 48, and "0" is a two-character array {'0', '\0'}.

Watch out The array must have room for the terminator. "cat" needs 4 slots, "hello" needs 6, a word of up to 80 characters needs 81. char word[5] = "hello"; compiles and silently gives you a non-string. What the terminator buys you

Because every string ends with a 0, string functions do not need a length parameter: they loop until they see '\0'. Remember that 0 is false, so while (s[i]) and while (s[i] != '\0') are the same test; write the explicit one.

// e_count(s) returns the number of 'e' characters in s
// requires: s is a valid string
int e_count(const char s[]) {
  assert(s != NULL);
  int count = 0;
  int i = 0;
  while (s[i] != '\0') {      // stop at the terminator; no length needed
    if (s[i] == 'e') {
      ++count;
    }
    ++i;
  }
  return count;
}

If the terminator is missing, that loop keeps going through memory until it happens to hit a 0 byte. Also note const char s[]: the function reads the string, so say so.

strlen

Definition — strlen (from <string.h>) strlen(s) returns the number of characters before the terminator. It is the length of the string, not of the array, and it does not count the '\0'. For char e[10] = "cat": strlen(e) is 3, sizeof(e) is 10. Computing it walks the entire string every time it is called.
#include <string.h>

// my_strlen(s) returns the length of the string s   (index notation)
// requires: s is a valid string
int my_strlen(const char s[]) {
  assert(s != NULL);
  int len = 0;
  while (s[len] != '\0') {
    ++len;
  }
  return len;
}

// my_strlen_ptr(s) returns the length of the string s   (pointer notation)
// requires: s is a valid string
int my_strlen_ptr(const char *s) {
  assert(s != NULL);
  const char *p = s;
  while (*p != '\0') {
    ++p;
  }
  return p - s;               // elements between the two pointers
}
Watch out — strlen inside a loop condition is "harshly penalized" 
for (int i = 0; i < strlen(s); ++i) {   // WRONG: strlen walks s on EVERY iteration
  ...
}

const int len = strlen(s);              // RIGHT: compute it once
for (int i = 0; i < len; ++i) {
  ...
}
The string does not change inside the loop, so re-measuring it is pure waste: a 1000-character string costs about 1000 × 1000 steps instead of 1000. The course explicitly says this will be harshly penalized on assignments and exams. Any time you write strlen, ask whether it is inside a loop.

Comparing strings: lexicographic order

Characters compare as numbers ('a' < 'b' is 1, because 97 < 98), but s1 < s2 or s1 == s2 on two strings compares their addresses, which says nothing about their contents. To compare contents we use lexicographic order and say a string precedes or follows another (not "smaller" or "greater", which could be read as length).

  1. Compare the first characters. If they differ, the string with the smaller character (by ASCII value) precedes the other.
  2. If they are the same, compare the second characters, and so on.
  3. If one string ends while the other continues, the shorter one precedes (its '\0', value 0, is smaller than any real character).
  4. Two strings are equal only if they have the same length and identical characters.
In lexicographic order:   ""   "a"   "az"   "c"   "cab"   "cabin"   "cat"   "catastrophe"
Remember ASCII: every uppercase letter (65 to 90) comes before every lowercase letter (97 to 122), and digits (48 to 57) come before both, so "Zebra" precedes "apple" and "9" precedes "A".
Definition — strcmp (from <string.h>) strcmp(s1, s2) returns 0 if the strings are identical, a negative integer if s1 precedes s2, and a positive integer if s1 follows s2. Only the sign is guaranteed; do not rely on the magnitude. Equality test: if (strcmp(s1, s2) == 0). Never if (s1 == s2).
// my_strcmp(s1, s2) returns 0 if s1 and s2 are identical, a negative value
//   if s1 precedes s2 and a positive value if s1 follows s2
// requires: s1 and s2 are valid strings
int my_strcmp(const char s1[], const char s2[]) {
  assert(s1 != NULL);
  assert(s2 != NULL);
  int i = 0;
  while (s1[i] == s2[i] && s1[i] != '\0') {   // walk while equal and not at the end
    ++i;
  }
  return s1[i] - s2[i];                        // chars are ints: the difference gives the sign
}

// my_strcmp("cab", "cat")  is 'b' - 't' = 98 - 116 = -18     (negative: "cab" precedes)
// my_strcmp("cat", "catastrophe") is '\0' - 'a' = 0 - 97 = -97  (the shorter string precedes)
// my_strcmp("b", "b")      is '\0' - '\0' = 0                 (identical)
Why checking only s1[i] != '\0' is enough The loop runs while the two characters are equal. If s1[i] is '\0' and the characters are equal, then s2[i] is '\0' too, so checking one terminator covers both. If the characters differ, the loop stops anyway and the difference tells you the order.

strcpy and buffer overruns

Definition — strcpy(dest, src) Overwrites dest with a copy of src, including the terminator. It returns the address of dest (historical, usually ignored). Requirements you must guarantee: dest has room for strlen(src) + 1 characters, and the two regions do not overlap.
// my_strcpy(dest, src) copies the string src into dest and returns dest
// requires: dest has room for strlen(src) + 1 chars [not asserted]
//           dest and src do not overlap [not asserted]
// effects: modifies dest
char *my_strcpy(char *dest, const char *src) {
  assert(dest != NULL);
  assert(src != NULL);
  int i = 0;
  while (src[i] != '\0') {
    dest[i] = src[i];
    ++i;
  }
  dest[i] = '\0';             // the loop stops BEFORE copying the terminator: add it yourself
  return dest;
}
Watch out — buffer overrun Writing past the end of dest is a buffer overrun (buffer overflow). C does not check, so the extra characters land in whatever lives next in memory: another variable, a return address. This is the classic source of C crashes and security holes. Also never let the regions overlap: strcpy(s + 4, s) on "spam" overwrites the source's terminator as it copies and fills memory with spamspamspam... until something crashes.

strcat

Definition — strcat(dest, src) Appends (concatenates) a copy of src to the end of dest, overwriting dest's terminator and adding a new one. dest must have room for strlen(dest) + strlen(src) + 1 characters: "cat" + "dog" needs 3 + 3 + 1 = 7.
// my_strcat(dest, src) appends src to the end of dest and returns dest
// requires: dest has room for strlen(dest) + strlen(src) + 1 chars [not asserted]
// effects: modifies dest
char *my_strcat(char *dest, const char *src) {
  assert(dest != NULL);
  assert(src != NULL);
  my_strcpy(dest + strlen(dest), src);   // copy src starting at dest's terminator
  return dest;
}

int main(void) {
  char s[7] = "cat";          // 7 = 3 + 3 + 1
  my_strcat(s, "dog");
  assert(strcmp(s, "catdog") == 0);
  assert(strlen(s) == 6);
}

5.4 String I/O

Definition — %s printf("%s", s) prints the characters of s up to (not including) the terminator.
scanf("%s", s) skips leading whitespace, reads one word (stops at the next space or newline), stores it in the array and adds the '\0'. Two things to notice: there is no &, because an array name is already an address; and with no width this call can write past the end of the array, so in CS 136 always give a width: for char name[81] write scanf("%80s", name): at most 80 characters are read, leaving one slot for the terminator.
#include "cs136.h"

int main(void) {
  char name[81] = "";              // 80 characters + '\0'
  printf("Enter your name: ");
  if (scanf("%80s", name) == 1) {  // NO &: name is already an address. Width 80 = 81 - 1
    printf("Hello, %s!\n", name);
  }
}
Worked example — what happens without the terminator 
char a[7] = "I like ";   // "I like " is exactly 7 characters: no room for '\0'
printf("%s", a);         // prints I like  ... and then keeps printing bytes from memory
printf("CS136\n");       //        until it stumbles on a 0 byte
In the course's edX demo the bytes that followed a happened to spell UofT not, so the screen read I like UofT not CS136. The fix is char a[8] = "I like ";. Whenever a %s prints garbage, suspect a missing terminator first.

Reading several words

int main(void) {

  while (scanf("%9s", name) == 1) {    // one word per iteration, at most 9 chars each

  // input "Samantha Bob": the loop greets Samantha, then Bob, then scanf returns EOF

Worked example — the overrun that changes your bank balance 
int main(void) {

  int balance = 100;

      break;
    }

Type zzzzzzzzzzzz (12 letters) and the four characters that do not fit in command are written into the next variable in memory. In the course's layout that is balance, whose four bytes become 'z' 'z' 'z' 'z' (0x7A each), and balance prints 2054847098. The int is just a re-interpretation of the same four bytes. One missing width specifier, and the program's data is corrupted silently.
Rules — what to use, what not to use
  • fgets reads a whole line safely (stops at '\n' or when the array is full; returns the array's address or NULL). It is safe but disallowed in CS 136.
  • gets has no size limit at all; it has been removed from the language since C11. Never use it.
  • The CS 136 way to read text that may contain whitespace: one character at a time with scanf("%c", &c) (note the & here: a single char is a variable, not an array), or one word at a time with a width.

5.5 String literals, arrays vs pointers, arrays of strings

Definition — string literal Any "double-quoted text" that is not initializing an array is a string literal: printf("hello\n"), strcmp(s, "quit"), char *p = "cat". For each literal C creates a null-terminated const char[] in the read-only data section (the "literal pool") before the program runs, and replaces the literal in your code with its address. Modifying a literal is undefined behaviour and an error in edX.
const char hidden[6] = "hello";   // what C secretly makes for the literal below (read-only)

int main(void) {
  printf("%s\n", "hello");        // the literal is really an address, like printf("%s\n", hidden)
  char *p = "cat";                // p holds the address of a read-only 4-char array
  // p[0] = 'b';                  // ERROR / undefined: writing into read-only data
  p = "dog";                      // fine: p itself is mutable, it now points at a different literal
  char a[] = "cat";               // a is a 4-byte array on the STACK, copied from the literal
  a[0] = 'b';                     // fine: a's elements are mutable ("bat")
  // a = "dog";                   // ERROR: an array cannot be assigned
}

A pointer to a literal is the opposite: a mutable pointer to constant data. In most expressions a and q are interchangeable; the differences are exactly the sizeof and the &a == a fact above.

Arrays of strings

★ Must remember — Chapter 5
  • Arrays: fixed length, same type, indices 0 to len - 1; define with a literal number (int a[6] = {...}); partial initialization zero-fills; {0} zeroes everything; uninitialized local = garbage, global = zeros.
  • Cannot: assign a whole array after definition, copy with =, compare with ==, change the length, or ask the array for its length. Keep const int a_len = 6; after the array and pass len to functions.
  • Size vs length: sizeof(int a[6]) = 24 bytes; length 6. Elements are contiguous; a == &a == &a[0] (same value, different types); *a == a[0].
  • Parameters: int f(const int a[], int len) (same as const int *a); only the address is copied; a declared length in brackets is ignored; the function can mutate the array unless const; call with a, never &a; assert a != NULL and a condition on len, document the rest [not asserted].
  • Pointer arithmetic: p + i moves i * sizeof(*p) bytes; p - q counts elements (same array only); no p + q; a[i] is *(a + i); no bounds checking. values example: p2 - p1 is 3 and p2[-2] is 30.
  • Strings: char array ending in '\0' (value 0; '0' is 48). "cat" needs 4 slots; char s[] = "cat" is the only allowed automatic length. strlen excludes the terminator; sizeof("hello") is 6, strlen 5.
  • Never call strlen in a loop condition (harshly penalized): const int len = strlen(s); first.
  • strcmp: 0 equal, negative s1 precedes, positive follows; equality is strcmp(a, b) == 0; == compares addresses. Lexicographic: "" "a" "az" "c" "cab" "cabin" "cat" "catastrophe"; uppercase before lowercase.
  • strcpy / strcat: destination needs strlen(src) + 1 / strlen(dest) + strlen(src) + 1 slots (3 + 3 + 1 = 7); no overlap; overrun corrupts neighbouring memory.
  • I/O: printf("%s", s) prints to the terminator (missing terminator prints garbage); scanf("%80s", name) reads one word, always with a width, no &; fgets safe but disallowed; gets never; CS 136 reads one %c at a time for text with spaces.
  • Literals live in read-only data as const char[] and are replaced by their address; never modify one. char a[] = "cat": 4-byte stack array, elements mutable, a not reassignable. char *p = "cat": 8-byte pointer, reassignable, characters not.
  • Arrays of strings: char *c[3] = {"Red", "Green", "Blue"}; c[0][1] is 'e'; c[1] is a pointer, not a char; pass the length. Oversized arrays: struct with data, len, maxlen, passed by pointer. 2D data: data[row * NUMCOLS + col].

  3. Copy each argument value into the frame (pass by value).
  4. Jump to the start of the function; locals get values when their definitions run.
  5. On return: jump back to the return address, pop the frame. The return address is a location in the caller, nothing to do with return statements.

1 · "How long is it?" — array vs pointer vs string

The one rule C stores the length of nothing. An array's length is a number you wrote in its definition; a pointer knows only one address; a string is the single exception because you can find its end by walking to '\0'. So: array length comes from the definition or a len parameter, pointer length does not exist, string length is strlen.

  • Read right to left: int * const p is "p is a const pointer to int"; const locks whatever is immediately to its left.
  • Passing a char * to a const char * parameter is fine. Passing a const char * to a char * parameter is a compile error ("discards qualifiers"), even if the function never writes.

12 · Exam fine print (from the Fall 2022 instructions; expect the same)

  • Interface requested → full documentation. "Write" or "implement" or "complete" → documentation not required, but you must still assert every requirement that can be asserted.
  • Helpers are allowed, must be at module scope (outside main) with a brief purpose statement, and on the exam you do not need to declare a helper before using it.
  • const is mandatory on array and pointer parameters you do not mutate.
  • Every array parameter has length at least one, so a[0] is a safe starting value for a min or max.
  • Integer overflow may be ignored unless the question raises it (then use INT_MAX on the safe side of the comparison).
  • No #include needed unless asked; cs136 module functions (read_int) are not allowed; provided code may be assumed to have its includes.
  • The reference page gives INT_MIN, INT_MAX and ASCII codes; using the numbers in code instead of 'a' is poor style and costs marks.
  • Only language features from the covered sections; for you, Sections 1 to 5 (no modules, no extern, no opaque structures, no heap).
  • Interpretation questions are not answered: state your assumption in the margin and proceed.
  • Extra space is at the back; write "continued on page N" in the answer box. Answer space is not a hint about length.

Pre-hand-in checklist (run it on every code answer)

  1. Does every parameter have a type? Is const on every array or pointer you only read?
  2. Do the names in the body match the parameter names in the header?
  3. Purpose line: does it name the function and say what it returns, prints or reads? Are requires: and (if needed) effects: there?
  4. Are the requirement asserts the first lines inside the function?
  5. Is every variable initialized? Is the loop variable declared in the for?
  6. Did you check the smallest inputs (0, 1, one digit, empty string, length 1) against your base case or loop bounds?
  7. Does every path of a non-void function hit a return? Does every loop path move toward the exit?
  8. In main: is every test variable defined with a type (and size for arrays) BEFORE it is used? Is each assert comparing to an expected value? Did you pass a, not &a?
  9. Scan for = inside conditions, < vs <=, a missing ; after a struct or a prototype, void in an empty parameter list.
  10. If the function is a harness: is it void, does it check scanf(...) == 1, and does it print a newline after each value?
